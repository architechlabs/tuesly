# H12X2 warm/cool LED driver

## Observed on the user's label

- Model marking: `H12X2-15W/17W/18W/20W`.
- Marking: `Sigmesh Powered By tuya`; no separate manufacturer identified.
- Input: 110–265 V AC, 50/60 Hz.
- Output: DC 27–38 V; maximum 20 W / 480 mA.
- Printed dimming range: 5–100%.
- Output terminals: `+`, `C`, `W`, indicating a warm/cool white arrangement.
- Selectable output ratings shown on the casing. The photo does not establish
  the switch positions or actual configured current rating.

## Observed over Bluetooth

- Address: `DC:23:52:81:60:BB`.
- Advertised Mesh Proxy Service: `1828`.
- Standard GATT Mesh Proxy input/output handles: 32 / 28, confirmed through
  the ESPHome receiver at 192.168.20.181.
- Vendor service 7FDD duplicates the 2ADD/2ADE UUIDs; select the standard 1828
  characteristic objects.
- Paired in Tuya Smart. No export of its current mesh keys is available.

## Expected control path; not yet verified on this firmware

Tuya documents standard SIG lighting models for on/off (1000), brightness
(1300), and CTL temperature (1306). Those are candidates for this CCT device,
not a claim that the exact H12X2 firmware exposes them. Query and parse its
Composition Data after authenticated mesh access is established. Bind and
address each model at the actual element address returned by the node.

`lib/tuesly_mesh/sig_lighting.py` implements the standard command/status codecs
and element discovery. Version 0.2.0 connects these to an HA light controller.
Tests use synthetic standard-format packets, not driver captures.

The protocol permits temperatures 800–20000 K; this is not the lamp's physical
colour-temperature range. Query the node's CTL temperature range and verify it
against the fixture before setting HA limits. The label does not supply Kelvin
limits, company/product IDs, supported model bindings or mesh keys.

## Hardware acceptance still pending

Version 0.2.0 implements durable mesh/address/sequence ownership, journaled
PB-GATT provisioning, proxy filtering/SAR, authenticated configuration replies,
model binding and an HA light entity. It is a development release pending live
HAOS installation and commissioning/control of this specific driver. Physical
reset must intentionally replace the existing Tuya Smart pairing; use the
manufacturer's instructions rather than guessing a power-cycle sequence.

## 2026-10-09 transport recovery

Dedicated proxy firmware 1.1.2 was compiled and flashed on COM8 with Wi-Fi power
saving disabled. Three post-flash authenticated API/entity checks returned all
14 entities in approximately one second each. During live HA retries, USB
reported connection establishment failures. Pausing the target Tuesly entry
and testing with a single diagnostic Bluetooth subscriber then succeeded:
GATT service discovery through the ESP32, RSSI -67 dBm, advertised 1828.
The test performed no mesh writes and disconnected its own session afterward.

Tuesly 0.2.3 corrects CTL Range Get to target model 1303 rather than 1306,
adds the missing CTL binding to saved nodes, and uses safe 23-byte-MTU Proxy SAR.
HA must load the new code and regain the Bluetooth subscription before lighting
acceptance can proceed. This GATT result does not prove the HA mesh credentials
or actual light commands.

## 2026-10-09 authenticated lighting recovery

After reset, PB-GATT provisioning completed with six elements. The measured
Composition Page 0 has the complete Lightness/CTL servers on the primary
element and five auxiliary OnOff-only elements. Version 0.2.4 selects the
unique Lightness channel and defers Composition Get until proxy authentication.

Authenticated hardware tests confirmed OnOff and Lightness responses, all
four model bindings, off, on at 128/255 and on at 220/255, then restoration to
242/255. The capture is `reports/configured-hardware.json`; it contains no keys.
The driver never answered CTL Temperature Range Get. The integration therefore
exposes brightness and on/off without inventing physical Kelvin limits.

Version 0.2.5 keeps an authenticated GATT connection across reads and commands.
The shared SIG radio owner releases its connection when another coordinator
needs it, on a session failure, or on integration unload. This avoids repeating
connection establishment for every 30-second poll. Multi-device scaling and
long-term reliability still require additional hardware acceptance.

HAOS live acceptance of 0.2.5: `light.tuesly_light_81_60_bb` loaded, with
off and brightness 128/255 and 220/255 confirmed through HA service calls.
Commands took about 1–2 seconds after connection establishment. Subsequent
authenticated refreshes remained available over several polling intervals;
no new Tuesly disconnect errors were recorded in that short observation.
Both the ESPHome provider and Tuesly entry were left enabled. This is not a
long-duration soak test or proof of colour-temperature support.


## 0.2.6 / firmware 1.1.4 validation candidate

The earlier short 0.2.5 observation was followed by loss of connectivity after
power cycling; it did not establish persistent pairing. The updated bench run
after intentional Smart Life removal/reset completed PB-GATT with six elements,
both Tuya vendor models and all advertised application models bound in 7.72s.
Authenticated OnOff, Lightness and relative warm/cool status were read on the
same bearer. A subsequent standalone reconnect did not see a fresh target
advertisement within its 12-second scan window. Reconnect, normal driver power
cycle and HA acceptance remain required; no production sign-off is implied.

The driver does not answer CTL Range Get. Tuya's documented 800..20000 CTL scale
is exposed as a relative warm/cool percentage, not an invented optical Kelvin
range. `reports/recovery-provisioning.json` records the measured binding result.
